# psd-slim — PSD 卡顿体检与精准瘦身

给「清理过还是卡」的大 PSD 用。通用清理脚本查的是空图层、隐藏图层、废弃样式；本工具查的是另外两类真凶——**图层边界被撑爆**和**路径锚点爆炸**——这两项通用脚本不检查。

## 两个工具

| 工具 | 干什么 | 怎么用 |
|---|---|---|
| `psd_doctor.py` | 不开 PS，直接读二进制，告诉你这文件为什么卡、能省多少 | 把 .psd 拖到 `体检.bat` 上；或 `python psd_doctor.py "文件.psd"` |
| `PsdSlim.jsx` | 在 PS 里执行修复，输出 `_lite` 副本 | PS → 文件 → 脚本 → 浏览… → 选 `PsdSlim.jsx` |

体检器加 `--fast` 可跳过 alpha 解码，快很多，但查不出幽灵层。

## 查什么、修什么

### ① 幽灵层 —— 内存杀手

图层的标称边界被撑到整张画布，实际内容只有几十像素。一个 6700×11387 的幽灵层在内存里是 **305 MB**，滚动一下、落一笔，PS 都要把它重算一遍。

**修法**：在它下方插一个空图层，再向下合并。空层边界为 0，合并后的并集边界就是真实内容边界。

**代价**：零。脚本只对「无样式 / 无蒙版 / 无剪贴 / 100% 不透明 / 正常混合 / 可见」的层动手，此时合并结果与原样逐像素一致。不满足条件的会被跳过并在报告里列出原因。

### ② 疯狂路径层 —— 重绘杀手

形状图层的矢量蒙版有几万个锚点。典型成因【推测】：「选区 → 建立工作路径 → 转形状」把一张带噪点的位图整个描摹了，几万条独立子路径。PS 每次重绘都要重新光栅化。

**修法**：栅格化形状（`图层 → 栅格化 → 形状`）。

**代价**：以后不能再拖锚点改形状。视觉上 PS 用的是同一套抗锯齿渲染，几乎无差。脚本只动「填充层 + 矢量蒙版 + 边界 ≥ 800×800」的层，小图标形状一律放过。

### ③ 兼容合成图 —— 看得见省不掉（CC2019）

PSD 尾部存着一张整幅平面化合成图，通常占文件的 20–30%，只用于让别的软件（AI、ID、看图工具）预览。

⚠ **2026-08-26 实测（CC2019 / 20.0.1）：对 8-bit PSD，无论首选项还是脚本参数怎么关「最大化兼容」，CC2019 都照写完整合成图，这块省不掉。** 体检报告里列它是为了让你知道体积去向，别指望砍掉它。（更新版本的 PS 是否如此【未验证】。）

### ④ 可选项（默认不动）

| 项 | 说明 | 为什么默认不动 |
|---|---|---|
| 栅格化智能对象 | 省掉嵌入的原始文件 + 滤镜缓存 | 智能对象通常是你还要改的东西 |
| 删 Alpha 通道 | 每次刷新少算一整张画布 | 那可能是你存着有用的选区 |
| 降画布尺寸 | 提速最猛，像素量按平方降 | 不可逆，细节永久损失 |

要开就改 `PsdSlim.jsx` 顶部 `CFG` 里的开关。

## 安全保证

- **原文件永不被修改。** 脚本第一步就另存出 `_lite` 副本，此后所有操作都在副本上。
- 第一次用建议先把 `CFG.reportOnly` 改成 `true` 跑一遍，只看报告不动手。
- 执行前会弹窗列出将要处理的图层，确认后才开始。
- 出错时整个流程中断并提示，原文件不受影响。
- 处理完在副本旁写一份 `_lite_日志.txt`。

## 顺带：PS CC2019 大文件性能设置

文件之外，这几项对超大文档影响很大（`编辑 → 首选项`）：

| 位置 | 建议值 | 原因 |
|---|---|---|
| 性能 → 内存使用 | 70–80% | 默认偏保守 |
| 性能 → 高速缓存级别 | 6（大文档档位） | 缩放和滚动会明显变顺 |
| 性能 → 高速缓存拼贴大小 | 1024K | 大文档少量大块比多量小块快 |
| 性能 → 图形处理器 | 勾选，高级设置选「高级」 | 走 GPU 合成 |
| 性能 → 历史记录状态 | 20 以内 | 每一步都占暂存盘 |
| 暂存盘 | 单独一块 SSD，别跟系统盘同盘 | 大文档一定会溢出到暂存盘 |

## 怎么避免再长出幽灵层

【推测，未逐一验证】常见成因是**大范围擦除不会缩小图层边界**——用橡皮或删除选区把一个满画布的层擦得只剩一角，PS 仍按满画布记账。养成习惯：大面积擦除之后，`Ctrl+A` → `Ctrl+X` → `Ctrl+Shift+V`（原位粘贴），边界就重算了。或者隔段时间跑一次体检器。

## 已知实测结果

对 `独角兽.psd`（2026-08-26 实测，CC2019 / 20.0.1 通过 COM 驱动执行）：

| 项 | 数值 |
|---|---|
| 处理前 | 308.2 MB，画布 6700×11387，293 图层 |
| 幽灵层 | 8 个（内存合计 2.3 GB）→ 全部无损重建，如 6700×11387 → 42×252 |
| 疯狂路径层 | 10 个、47.5 万锚点 → 全部栅格化，锚点归零 |
| 处理后 | 255.0 MB（-53 MB；体积大头 71.5MB 合成图在 CC2019 中不可去除） |
| 视觉验证 | 对比处理前后 PS 自渲染的合成图：76.3M 像素中 99.85% 差值 ≤1/255，最大差 32/255 仅 540 像素，全部位于栅格化边缘的抗锯齿上 |
| 耗时 | 122 秒（含两次 300MB 级写盘） |

体积只降了 17%，但卡顿的两大真凶（幽灵层重算、路径重光栅化）已归零——**卡不卡看的是这两项，不是文件大小**。
